## 1. What this app is
"Slipstream" (UI) / Convoy (repo): a passenger-side multiplayer map for riders — live nearby riders, convoys with chat and walkie-talkie voice (WebRTC mesh + WS relay), routing/ETA, police/radar/scanner/aircraft/traffic overlays, drag-timer and race modes, HUD instrument cards. Live at https://odoreeci.tech (Caddy → Node on VPS 2.25.184.90) and as a Capacitor Android APK with an OTA channel (`/api/ota`). Real riders use production — treat it gently (one request is a measurement, a loop is an attack).

## 2. Stack & layout
- **Frontend:** vanilla ES5-style JS, no bundler/framework. `index.html` (shell, CSP meta, 38 `defer` scripts + `css/styles.css`, all stamped `?v=cyNNN`), `js/*.js` (44 modules total on `window.App` — `js/data.js`, `js/voice.js`, `js/radar.js`, `js/scanners.js`, `js/race.js`, `js/dragy.js` are all on disk but no longer `<script>`-tagged; each loads lazily via `A.data.ensure()` / `A.voiceLoader.ensure()` / `A.lazy.radar()` / `A.lazy.scanners()` / `A.lazy.race()` / `A.lazy.dragy()`, see §5). Boot: `js/app.js` → `mapview.init()` → 20+ `*.init()` → `auth.boot()`. Global state + event bus: `js/state.js` (`A.state.on/off/emit`). WS client: `js/net.js`. Telemetry: `js/telemetry.js` (batched, `sendBeacon`).
- **Map:** MapLibre GL 5.24.0 (jsdelivr pin), vector tiles from `tiles.openfreemap.org` / `basemaps.cartocdn.com`; 14 layers in `js/mapview.js` (`setData()` at `:433` is the single fan-in).
- **Server:** `server/server.js` (HTTP + `ws`, 1 Hz tick, `scopeFor()` per viewer), `server/httpcache.js` (static cache policy), `server/telemetry.js`, `server/overpass.js`, `server/hotspots.js`, `server/store.js`/`db.js`/`supabase.js` (accounts in Supabase Postgres; realtime state in memory + JSON under `server/data`). Node ≥ 18 (box: v26.5.1).
- **Native:** `android/` (Capacitor 8; plugins for background location, BLE radar, voice, OTA) — code-only here; shipping needs the human's keystore.
- **Tooling:** `test/run.js` (40 suites), `test/frontend.test.js` (jsdom + axe-core + html-validate + impeccable detector + ratchet on `test/frontend-baseline.json`), `scripts/pack-ota.js`, `scripts/copy-web.js`, `release.js`, `deploy/live-deploy.sh` + `deploy/PUSH-RUNBOOK.md`. Knowledge graph: `graphify-out/graph.json`.
- **Generated / never edited:** `www/`, `ota-out/`, `graphify-out/` (regenerate with `graphify update .`).

Stamp rule: a stage that edits `index.html`/`css/`/`js/`/`legal/` bumps every `?v=cyNNN` stamp by one (`sed -i 's/?v=cyOLD/?v=cyNEW/g' index.html`, then re-run `node scripts/pack-ota.js --offline 2>&1 | tail -6`). Server-only stages do not bump. **Never hardcode "now" here — read it.** The rule is: if any file under `index.html`/`css/`/`js`/`legal/` differs from `git show origin/main:<file>`, the local stamp must be **strictly greater** than the pushed stamp; otherwise it must not be **behind** the pushed stamp. `node test/stamp.test.js` (see §9) computes and enforces this from `git` every run, including an embedded regression fixture proving it catches a stage that changes web files without bumping. **Why this note exists:** cycle 1 of this mission shipped three real bug fixes under a stamp that was never bumped, because this section used to state the current local/production stamps as a remembered fact — a sentence that went stale the moment the very next push landed, and two independent stages (an implementer, then a reviewer) both correctly followed the by-then-false sentence. Don't restate the current numbers here; run `node test/stamp.test.js` or `git show origin/main:index.html | grep -oE '\?v=cy[0-9]+' | head -1` instead.

## 5. Current milestone
**Cycle 12: T2.6b shipped (server-only, unpushed) — WS `permessage-deflate` turned on, plus a corrected P-E ruler.** Numbers are in §6; this section is the "how/why".
1. **Why**: the cycle-11 handoff named T2.7 (hotspot flush) as P-E's next byte lever. First measurement this cycle (`node test/wire-bench.js --clients 60 --secs 10`) showed `byKindBytesPerSec` has exactly one key, `tick` — hotspot/chat/party/global traffic is zero bytes in this bench, so a hotspot fix can't move the byte bar by construction. That inherited claim was wrong; T2.7 is a CPU item only (point 4).
2. **`test/wire-bench.js` now measures real TCP bytes.** `connectClient()` captures the socket off `ws`'s public `'upgrade'` event and samples `socket.bytesRead` at the same gate-open/close instants already used for `bytesByKind`. New field `wireBytesPerClientPerSec` (real wire bytes) alongside the old `bytesPerClientPerSec` (post-inflation — protocol efficiency, expected flat under compression). Also added `--profile` (`--cpu-prof` on the server child; needs a clean exit to flush, so `test/server-stub.js` now installs `process.on('SIGTERM', () => process.exit(0))`) and `serverRssKb: {start, end}` (`/proc/<pid>/status`).
3. **`server/server.js:4036`, `WebSocketServer`'s `perMessageDeflate`.** `threshold: 0` (ws's 1024B default would compress nothing at our ~150-500B rows — load-bearing); `zlibDeflateOptions: {level:6, memLevel:7}`, `serverMaxWindowBits: 11`, `concurrencyLimit: 10` (frugal memory, ≈100KB/connection, over `ws`'s w15/m8 default which measured only marginally better on our row shape — 0.243 vs 0.254 ratio — for 10× the memory). Never forces `clientMaxWindowBits` (some clients reject it, killing the whole extension). `WS_DEFLATE=0` env var = same-code kill switch. New `test/wsdeflate.test.js` (40th suite, 7 checks): boots a real server child, connects a close-together GUEST PAIR (a lone guest's `c.known` is empty and never gets a `tick` frame — server/server.js:3350/3378 both `continue` on that), asserts `ws.extensions` (the client's own getter) contains `permessage-deflate`, asserts row shape/precision survive compression, asserts `WS_DEFLATE=0` empties `ws.extensions`. RED→GREEN proven by forcing `perMessageDeflate: false`.
4. **The fast-lane "~100ms tick" question, settled as bench-parent/box contamination, not a fixed cost.** `--cpu-prof` (N=60, 10s): idle dominates; among non-idle time, `processChunk [node:zlib]`/`writev` (T2.6b's own new compression+write cost) now outweigh app logic (`rowOf`/`shouldSend`). Separately: this stage's own repeated identical-code runs show `fast350` p50 swinging ≈3-4ms (5 runs) vs ≈90-100ms (2 runs) with zero code change — the contamination signature (bench parent runs 60 `JSON.parse` clients in the same process, competing with the server child and the box's foreign Chromium session, §8 item 8). **Retired as a P-E gating criterion this cycle** — informational only, permanently; watch `processChunk`/`writev` if a future cycle profiles T2.6b's own CPU cost.
5. **Found & fixed along the way**: `test/wire-bench.js`'s "every frame was tick" check wasn't gated to the fast default-mode window and started failing at N=60 once compression's extra CPU cost pushed wall-clock past the pre-existing 45s `t:'global'` broadcast (unrelated `setInterval`) — now accepts `'global'` too, still catches a genuinely wrong kind.
Not done: `test/concurrency.js` rewrite onto the stub; any push (Lane B-shippable, but only the push stage deploys); shortening rider ids.

## 7. Invariants / guardrails
1. No bundler, framework, TypeScript, or runtime dependency; lazy loading = `<script>` insertion with the same `?v=` stamp. `playwright` never enters `package.json` (scratch install only).
2. CSP allowlists (`index.html` meta + `server/server.js`), auth, and the two CDN pins change only when the milestone says so and `test/serverpolicy.test.js` passes.
3. Only the push stage deploys (`deploy/live-deploy.sh update|release`); other stages may run `diag` once. Stamp rule + stamp parity (§3). `pack-ota.js` ships the whole `www/`.
4. `test/frontend-baseline.json` ratchets down only (`testBaselineRatchet()`); new keys start at their measured value; a retired key never silently reappears higher.
5. **No number, no claim:** a performance change lands with a before/after from `test/perf-bench.js` or the field `vitals`.
6. Keep the visual identity (17 allowlisted detector findings, `css/DESIGN-DECISIONS.md`); reduced-motion seeding in `js/state.js:30-31` is correct; `fetchPolice`/`fetchWaze` are alerting paths — never blanket-pause or lazy-gate them.
7. Every stage: `graphify query` before editing, `graphify update .` after; `npm test` + `npm run test:frontend` green at the end; suite count and per-suite check counts never go down.
8. A swallowed-exception line in the production journal (`[handler …]`, `[defer] …`, `uncaughtException`) is a test gap: the fix is an executed test, never an allowlist or a log grep.
9. Never: build/upload an APK, `--force` an OTA, edit `/var/lib/convoy/*`, rename the product, loop requests at production or third parties.
